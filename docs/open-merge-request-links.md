# Как открывать ссылки на MR в GitHome

Если Paseo, почта или другое приложение открывает обычную HTTPS-ссылку в Chrome, расширение может передать её в GitHome. Chrome при этом остаётся браузером по умолчанию. Остальные ссылки открываются как обычно.

## 1. Проверьте GitHome

Установите актуальную сборку GitHome с поддержкой ссылок `githome://` и добавьте подключение к своему GitLab. На Ubuntu/Debian используйте пакет `.deb`, на macOS установите приложение в папку `/Applications`.

Перед настройкой расширения проверьте запуск из терминала. Замените ссылку в примерах на ссылку на доступный вам MR.

**Ubuntu/Debian**

```bash
/opt/GitHome/githome --open-mr 'https://gitlab.example.com/team/project/-/merge_requests/42'
```

В исправленном пакете `.deb` можно использовать короткую команду `githome --open-mr '…'`.

**macOS**

```bash
/Applications/GitHome.app/Contents/MacOS/GitHome --open-mr 'https://gitlab.example.com/team/project/-/merge_requests/42'
```

Откроется окно GitHome с указанным MR. Если приложение уже запущено, MR откроется в нём же.

## 2. Установите расширение GitHome для Chrome

1. Скачайте `githome-chrome.zip` из [релиза GitHome](https://github.com/js2me/githome/releases/latest) и распакуйте. Если вы работаете с исходниками, используйте папку [`extensions/chrome`](../extensions/chrome/).
2. Отключите старое правило для GitHome в **External Application Launcher**, если оно есть. В GitHome оставьте выключенной системную опцию **Настройки → Оформление → Открывать ссылки на MR из других приложений**.
3. Откройте `chrome://extensions`, включите **Режим разработчика**, нажмите **Загрузить распакованное расширение** и выберите папку с `manifest.json`.
4. Нажмите значок **GitHome** в Chrome. Укажите адрес сервера без пути к проекту, например `gitlab.example.com`, нажмите **Сохранить** и разрешите доступ к этому сайту.
5. Нажмите обычную HTTPS-ссылку на MR в Paseo. Если Chrome запросит подтверждение, нажмите **Открыть GitHome**.

Расширение не требует отдельного помощника. Если Chrome не запустил GitHome автоматически, нажмите **Открыть в GitHome** на странице расширения. Кнопка **Открыть в GitLab** откроет исходную ссылку в Chrome. Если хотите всегда выбирать вручную, снимите галочку **Открывать автоматически**.

## Если не работает

- **Терминал пишет `/usr/bin/githome-bin: not found`.** Это ошибка старого пакета `.deb`. Переустановите обновлённую сборку. Для запуска старого приложения можно использовать полный путь `/opt/GitHome/githome`.
- **Chrome открывает страницу GitLab или не видит GitHome.** Проверьте, что адрес сервера сохранён и Chrome разрешил доступ к нему. На Ubuntu используйте установленный `.deb`, а на macOS перенесите GitHome в `/Applications` и запустите его хотя бы один раз.
- **GitHome не находит подключение.** Добавьте в настройках GitHome сервер, к которому относится MR. Адрес в Chrome не заменяет подключение в приложении.
- **Chrome сообщает, что он не браузер по умолчанию.** Выключите системную обработку ссылок в GitHome. Если Chrome не восстановился автоматически, снова выберите его браузером по умолчанию в настройках ОС.

## Вариант без расширения

На macOS и Ubuntu/Debian с пакетом `.deb` можно включить **Настройки → Оформление → Открывать ссылки на MR из других приложений**. GitHome станет системным обработчиком HTTPS и будет передавать обычные ссылки прежнему браузеру. При таком варианте Chrome может сообщать, что он больше не браузер по умолчанию. Чтобы вернуть прежний браузер, выключите эту опцию.
